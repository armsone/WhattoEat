# 서울 데이터 초기 조사 기록

> 아래 수치와 3개 부서·6개월 조건은 초기 조사 당시의 역사적 기록이다. 현재 기준은 최근 18개월·공공기관 식사 이용 1건이며, 최신 실행 방법과 정책은 [전국 데이터 문서](public-dining-national.md)를 따른다.

접근 경로 조사 결과:
- 서울 정보소통광장(`opengov.seoul.go.kr/expense`)은 직접 크롤링하지 않았다. 열린데이터광장 CSV 전량이 같은 원문을 담고 있고 문서 URL을 그대로 제공한다.
- OpenAPI 샘플키(`sample`)는 요청당 5건 제한이라 전량 수집에 부적합하다. 인증키는 생성·조회하지 않았다.
- 열린데이터광장의 `sheetView.do`는 첫 요청에서 "서비스 지연(103)" 오류를 냈으나 브라우저 헤더·Referer를 붙인 재요청에 정상 응답했고, CSV 다운로드 엔드포인트는 두 차례 모두 정상(HTTP 200, 65.6MB)이었다.

## 2. 생성 방법

```bash
# 1) 원격 CSV 전량 다운로드 → 축소 원자료·증거·카탈로그 생성 (기본)
python3 tools/build_public_dining_catalog.py

# 2) 이미 내려받은 전체 CSV(CP949) 사용
python3 tools/build_public_dining_catalog.py --full-csv /tmp/seoul-oa22156-full.csv

# 3) 저장소의 축소 원자료만으로 오프라인 재생성 (네트워크 불필요, 결과 동일)
python3 tools/build_public_dining_catalog.py --from-reduced
```

표준 라이브러리만 사용한다(Python 3.14에서 확인). 축소 자료는 식사 여부와 검증된 장소만 남긴 재집계용 자료이며 원문 사본이 아니다. 원자료 문서 링크와 해시로 출처를 추적한다.

## 4. JSON 구조

계약 필드(필수): `schemaVersion`, `generatedAt`, `coverageDescription`, `sourceURLs`, `restaurants[].name/address/departmentCount/lastPaymentDate/sourceURL`.

추가 필드:
- 최상위 `sourceDataset`(이름·제공기관·라이선스·출처표기·수집시각·SHA-256·행수), `aggregation`(창·추정 기준월·월별 부서 커버리지·임계값·제외 통계).
- 식당별 `district`(구), `firstPaymentDate`, `recordCount`, `medianAmountKRW`(식사 기록 집행금액 중앙값), `departments`(부서 키 목록), `sourceDocumentURLs`(최신순 최대 10개 문서 원문), `nameVariants`(원문 표기 변형).
- `sourceURL`은 가장 최근 식사 기록의 정보소통광장 문서 URL이다.

## 5. 거짓양성 방지 정책

1. **장소 형식**: `장소명 (주소)` 형식만 채택. 마지막 괄호를 주소로 보고 "외 N" 접미는 제거. 주소 없는 행·지번만 있는 행(예: `태평로1가 31-20`)·건물번호 없는 행(예: `사직로8길`)은 제외.
2. **주소 검증**: 도로명+건물번호 정규식(`…로|…길` + 숫자, `태평로1가` 같은 지번 배제)을 만족하고 `○○구`가 포함된 주소만 채택. 대표 주소는 서울 25개 구 포함 > "서울" 표기 포함 > 긴 문자열 순으로 고른다.
3. **비음식점 제외**: 장소명에 마트·쿠팡·편의점·백화점·온라인몰·문구·꽃집·베이커리·카페·커피 체인·매점·구내식당·급식업체(푸드테크 등)·법인 표기(주식회사·㈜·(주)·(유))·약국·병원·은행·센터·협회·재단·학교·공연 등의 키워드가 있으면 제외. 호텔 이름 자체로 끝나는 장소는 제외하되 `○○호텔점` 지점 표기는 허용.
4. **식사 성격 판정**: 집행목적에 간담회·식사·오찬·만찬·석식·중식·조찬·회식·급식·회의·격려·접대·초청 중 하나가 있고, 구입·구매·물품·상품권·선물·기념품·화환·경조·배송·커피·원두·도시락·케이크·떡·간식·음료·다과·비품·용품이 없어야 식사 기록으로 본다.
5. **임계값**: 식사 기록의 고유 부서가 3개 이상이고, 그 장소 전체 기록 중 식사 기록 비율이 70% 이상이어야 채택.
6. **부서 고유 키**: 전체부서명의 마지막 토큰(과·담당관 단위). `경제실 경제정책과`와 `경제정책과`처럼 상위 조직 표기 유무만 다른 경우를 한 부서로 합쳐 부서 수 부풀림을 막는다(충돌 15건 모두 같은 부서의 표기 차이임을 확인).
7. **병합 규칙**: 키 = (장소명 정규화[NFKC·소문자·공백/기호 제거], 서울+구+도로명+건물번호). 건물번호 하이픈을 보존하여 12-3과 123을 구분한다. 서울 외 지역이 명시되거나 서울의 구가 확인되지 않으면 제외한다. 도로명 안 띄어쓰기(`세종대로 14길`)만 통일한다. 같은 이름이라도 도로명·번호가 다르면 다른 지점으로 유지하고, 표기 오탈자 변형은 합치지 않는다.
8. **개인정보**: 작성자·전화번호·집행대상은 저장하지 않는다. 축소 원자료의 집행목적 원문은 식사 여부로 바꾸고, 집행장소는 검증된 상호·주소만 남긴다. 집행장소에 섞인 사업자 대표자명(`홍길동, 서울 중구 …`, `… 30/홍길동`)은 주소·장소명에서 제거하고, 원문 주소 변형 목록은 보존하지 않는다. 생성 후 전화번호·개인명 접두 패턴 검색 결과 0건.
9. **수치**: 모든 값은 원자료 행 집계이며 임의 선정·창작 없음. 필요한 시점에 위 명령으로 재생성한다.

## 6. 남은 제약

- 지번 주소만 적힌 장소(예: 태평로1가의 일부 식당)와 주소 없이 이름만 적힌 장소는 정책상 제외돼 실제 이용 식당보다 목록이 작다.
- 키워드 기반 비음식점 판정이므로 이름만으로 구분되지 않는 비음식점(예: 이름이 일반적인 법인)이 드물게 남을 수 있고, 반대로 `센터`·`대학`처럼 넓은 키워드 때문에 실제 식당이 빠질 수 있다.
- 2026-08 기록은 등록 진행 중 자료다. 다음 달 재생성하면 공개 현황 추정 기준월이 앞당겨진다.
- 서울시 본청 자료만 포함한다. 자치구·타 지역 확장은 별도 데이터셋이 필요하다.

앱은 실행일 기준 최근 6개월 이내 결제 기록을 추가 조건으로 적용한다. 따라서 내장 명단 548곳 모두가 항상 우선 표시 대상이 되는 것은 아니다.
